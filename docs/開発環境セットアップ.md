# 開発環境セットアップ手順（Windows）

旅ノート金沢（Kanazawa_Trip）の開発を始めるための手順です。3人全員が、それぞれ自分のパソコンで1回ずつ行います。

- 所要時間：30分〜1時間
- 対象：Windows 10 / 11
- 困ったら：エラーの画面をそのままチームに共有する

---

## 全体の流れ

| 手順 | やること | 回数 |
| --- | --- | --- |
| 0 | アカウントと招待の確認 | 最初の1回 |
| 1 | ソフトを3つインストールする | 最初の1回 |
| 2 | インストールできたか確認する | 最初の1回 |
| 3 | Git に自分の名前を登録する | 最初の1回 |
| 4 | リポジトリを clone する | 最初の1回 |
| 5 | `.env.local` を作る | 最初の1回 |
| 6 | 動かしてみる | 最初の1回 |
| 7 | ふだんの作業の流れ | 毎回 |

---

## 手順0：アカウントと招待の確認

| 確認すること | 誰が |
| --- | --- |
| GitHub のアカウントを持っている | 全員 |
| GitHub のリポジトリ `ponsuke108/Kanazawa_Trip` への招待（Collaborator）を受け入れた | 代表者以外 |
| Supabase の招待を受け入れた | DB担当（C）。A・B は任意 |
| 代表者から Project URL と Publishable key を受け取った | 代表者以外 |

> GitHub の招待は、届いたメールか GitHub の通知（右上のベルのアイコン）から「Accept invitation」を押して受け入れます。

## 手順1：ソフトを3つインストールする

| ソフト | 何に使うか | 入手先 |
| --- | --- | --- |
| Node.js | サイトを動かす・ライブラリを入れる | https://nodejs.org/ja |
| Git | コードの変更履歴を管理する | https://git-scm.com/downloads/win |
| VS Code | コードを書くエディタ | https://code.visualstudio.com/ |

### Node.js
1. https://nodejs.org/ja を開く
2. 「LTS」と書かれたボタンからダウンロードする
3. インストーラーを開き、初期設定のまま「次へ」で進める

### Git
1. https://git-scm.com/downloads/win を開く
2. 「Click here to download」からダウンロードする
3. インストーラーを開き、初期設定のまま「Next」で進める

### VS Code
1. https://code.visualstudio.com/ を開き、ダウンロードする
2. インストーラーを開く
3. 「追加タスクの選択」の画面で **「PATH への追加」** にチェックが入っていることを確認して進める

### インストールが終わったら
**パソコンを再起動する。** 再起動しないと、インストールしたソフトが認識されないことがあります。

## 手順2：インストールできたか確認する

1. VS Code を開く
2. 上部メニューの **ターミナル → 新しいターミナル** を開く
3. 次の3行を1行ずつ入力し、Enter を押す

```powershell
node -v
npm -v
git --version
```

次のように数字が出れば成功です（数字は多少違っても大丈夫）。

```
v22.x.x
10.x.x
git version 2.x.x
```

> **エラー「このシステムではスクリプトの実行が無効になっているため…」が出たら**
> 次を1回だけ実行し、確認を聞かれたら `Y` を入力して Enter を押します。
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

## 手順3：Git に自分の名前を登録する

コミット（変更の記録）に残る名前とメールアドレスです。GitHub に登録しているものと同じにします。

```powershell
git config --global user.name "GitHubのユーザー名"
git config --global user.email "GitHubに登録したメールアドレス"
```

## 手順4：リポジトリを clone する

clone ＝ GitHub にあるコードを、自分のパソコンにコピーすること。

```powershell
# 1. コードを置く場所（ドキュメントフォルダ）に移動する
cd ~\Documents

# 2. clone する（Kanazawa_Trip というフォルダができる）
git clone https://github.com/ponsuke108/Kanazawa_Trip.git

# 3. そのフォルダに移動する
cd Kanazawa_Trip

# 4. 必要なライブラリをインストールする（1〜2分かかる）
npm install
```

最後に `found 0 vulnerabilities` などと表示されて止まれば完了です。

## 手順5：`.env.local` を作る

`.env.local` ＝ 自分のパソコンでサイトを動かすときに、どの Supabase につなぐかを書いておくファイル。GitHub には上げない決まりなので、各自で作ります。

### 5-1. ファイルを作る

```powershell
Copy-Item .env.example .env.local
```

> エクスプローラーの右クリック→「新規作成」で作ると、名前が `.env.local.txt` になって読み込まれないことがあります。上のコマンドで作ってください。

### 5-2. VS Code でフォルダを開く

```powershell
code .
```

- 最後の `.` を忘れないこと
- 「このフォルダー内のファイルの作成者を信頼しますか？」と聞かれたら「はい」

### 5-3. 値を書き込む

1. 左側のファイル一覧から `.env.local` をクリックして開く
2. `=` の後ろに、代表者から受け取った値を **空白を入れずに** 貼り付ける

```
VITE_SUPABASE_URL=https://onkovqfkpthqovuswjuz.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_ここに受け取ったキー
```

3. **Ctrl + S** で保存する

### 守ること

- `.env.local` は GitHub に上げない（`.gitignore` で自動的に除外されている）
- 書いてよいのは **Project URL** と **Publishable key** の2つだけ
- Supabase の **Secret key（service_role）** はどこにも書かない・共有しない

> **代表者へ：** Project URL と Publishable key は、Supabase の **Project Settings → API Keys** で確認できます。

## 手順6：動かしてみる

VS Code のターミナルで次を実行します。

```powershell
npm run dev
```

1. `Local: http://localhost:5173/` と表示されたら、その文字を **Ctrl を押しながらクリック**
2. ブラウザが開き、「S-01 ホーム」と画面下部のタブが表示されれば **セットアップ完了**

| やりたいこと | 方法 |
| --- | --- |
| 止める | ターミナルで **Ctrl + C** |
| スマホの見た目で確認する | ブラウザで **F12** → 上部のスマホのアイコン → 幅を `375` にする |

## 手順7：ふだんの作業の流れ

### 7-1. 作業を始めるとき

VS Code で `Kanazawa_Trip` フォルダを開き、ターミナルで次を実行します。

```powershell
git switch main        # main に切り替える
git pull               # 最新の main を取り込む
npm install            # 他の人がライブラリを増やしていた場合に備える
git switch -c a/search-page   # 自分の作業ブランチを作る
npm run dev            # 動かしながら作業する
```

**ブランチ名のルール：** `担当/内容`（英小文字とハイフン）

| 例 | 意味 |
| --- | --- |
| `a/search-page` | A が検索画面を作る |
| `b/block-editor` | B がブロック編集を作る |
| `c/save-plan-rpc` | C がプラン保存の関数を作る |

### 7-2. 作業を記録する（コミット）

```powershell
git add .
git commit -m "S-02 検索条件画面にタグ選択を追加"
```

コミットのメッセージは「何をしたか」を日本語で短く書きます。

### 7-3. プルリクエストを出す前のチェック

```powershell
npm run typecheck
npm run lint
npm run format
npm run build
```

4つともエラーが出なければOKです。`npm run format` は書き方を自動で整えるので、実行した後にもう一度コミットします。

### 7-4. GitHub に送る（push）

```powershell
git push -u origin a/search-page
```

> 初めて push するときは、ブラウザで GitHub のログイン画面が出ます。ログインして「Authorize」を押せば、次からは聞かれません。

### 7-5. プルリクエストを作る

1. https://github.com/ponsuke108/Kanazawa_Trip を開く
2. 黄色い帯の **「Compare & pull request」** を押す
3. タイトルと説明を書く（テンプレートの項目を埋める）
4. **「Create pull request」** を押す
5. チームに「レビューお願いします」と伝える

### 7-6. レビューと取り込み

| 誰が | やること |
| --- | --- |
| 自動チェック（CI） | 型・lint・整形・ビルドを確認する。緑のチェックになるのを待つ |
| 自分以外の1人 | **Files changed** タブで変更を見て、**Review changes → Approve** を押す |
| プルリクエストを出した人 | 承認されたら **Squash and merge** → **Confirm** で main に取り込む |

main に取り込まれると、Vercel が自動で本番サイト（https://kanazawa-trip.vercel.app ）を更新します。

> **プレビューで確認：** プルリクエストには、Vercel が作った確認用URL（プレビュー）が自動でコメントされます。レビューする人はそれをスマホで開いて確認してください。

### 7-7. 取り込まれた後

```powershell
git switch main
git pull
```

次の作業は、また 7-1 から新しいブランチを作って始めます。

## 困ったとき

| 症状 | 原因と対処 |
| --- | --- |
| `node` や `git` が「認識されません」 | インストール後に再起動していない → パソコンを再起動する |
| 「スクリプトの実行が無効」 | 手順2の `Set-ExecutionPolicy` を実行する |
| `npm run dev` で「VITE_SUPABASE_URL と VITE_SUPABASE_ANON_KEY が設定されていません」 | `.env.local` がない、名前が違う（`.env.local.txt` など）、値が空 → 手順5をやり直す |
| `git push` で「rejected」「protected branch」 | main に直接 push しようとしている → 7-1 でブランチを作ってから push する |
| `git pull` で「conflict」 | 他の人と同じ場所を変更した → 無理に直さず、チームに相談する |
| プルリクエストの CI が赤（×） | 「Details」を押してエラーを確認し、手元で 7-3 のチェックを実行して直す |
| 画面が真っ白 | ブラウザで F12 → Console タブの赤いエラーを確認してチームに共有する |

## 参考：ターミナルの違い

Git Bash、PowerShell、VS Code のターミナルは、どれもコマンドを打つ画面です。どこから `git` を打っても、動くのは同じ Git です。**チームでは VS Code のターミナル（PowerShell）にそろえます。**

| やること | PowerShell（VS Code） | Git Bash |
| --- | --- | --- |
| ファイルのコピー | `Copy-Item .env.example .env.local` | `cp .env.example .env.local` |
| フォルダの移動 | `cd ~\Documents` | `cd ~/Documents` |
| `git` と `npm` のコマンド | 同じ | 同じ |
